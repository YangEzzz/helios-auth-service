# 公共图片上传

## 请求

`POST /api/v1/upload/image`

上传需要有效的 Helios 登录 Cookie 或 `Authorization: Bearer <token>`。
业务后端也可使用项目 HTTP Basic 凭据（项目标识 + 项目密钥），同时发送 `X-Helios-User-ID`，值必须来自业务后端已验证的登录会话。服务端重新校验项目凭据、用户启用状态及项目成员关系；仅有项目密钥或仅有用户 ID 均不能上传。项目密钥不得交给浏览器。
Cookie 请求沿用现有 CSRF 校验，需要可信 Origin 和匹配的 `X-CSRF-Token`。
跨域浏览器请求沿用服务端已配置的前端来源白名单，不自动向其他站点开放。

使用 `multipart/form-data`，文件字段为 `file`，每次上传一张图片。
可选字段 `md5` 为图片原始字节的 MD5（32 位十六进制，不区分大小写）；提供时服务端验证，错误返回 400。
支持 JPG/JPEG、PNG、GIF、WebP，文件不能为空，最大 10 MiB。
服务端校验扩展名与文件内容类型一致，拒绝 SVG 等格式，并限制整个请求体大小。

```bash
curl -X POST "$HELIOS_BASE_URL/api/v1/upload/image" \
  -H "Authorization: Bearer $HELIOS_TOKEN" \
  -F "file=@picture.png"
```

## 响应

成功返回 HTTP 200：

```json
{
  "code": 200,
  "message": "上传成功",
  "data": {
    "url": "/uploads/images/图片MD5.png",
    "size": 12345,
    "mimeType": "image/png",
    "md5": "32位小写十六进制摘要",
    "reused": false
  }
}
```

`url` 是相对于 Helios 服务域名的地址；其他应用应使用 Helios 的外部访问地址补全，不能使用自身域名补全。
前端提交 FormData 时让浏览器自动设置 Content-Type 和 boundary。
参数、格式或大小错误返回 HTTP 400；未认证返回 401；存储失败返回 500。
客户端应同时检查 HTTP 状态和业务 `code`。

## MD5 查询与重复上传

`POST /api/v1/upload/image/check`，使用与上传相同的登录鉴权和 Cookie CSRF 校验。
请求为 JSON：`{"md5":"图片原始字节的32位十六进制MD5"}`。

- 已存在：HTTP 200，`data` 包含 `exists: true`、`url`、`md5`、`size`、`mimeType`、`reused: true`，调用方直接使用地址，无需发送图片。
- 未存在：HTTP 200，`data` 为 `{"exists":false,"md5":"查询的摘要"}`，调用方再提交文件到上传接口。
- MD5 无效：HTTP 400；未登录：HTTP 401。

服务端始终按实际文件内容计算 MD5，不信任客户端摘要。即使没有预查询或未提供 `md5` 字段，相同内容再次上传也返回同一地址，`reused: true`，不重复写入文件。不同文件名及 JPG/JPEG 别名不影响去重。
首次写入先保存临时文件，再通过同目录硬链接原子发布；并发重复上传只生成一个最终文件，不返回尚未写完的文件。存储卷需支持硬链接（例如 NTFS/ext4）。复用时同时比对原始字节，检测到摘要碰撞或存储文件损坏时返回 500，不覆盖已有文件。
仅查询 MD5 可以避免网络重传；直接再次提交文件仍会传输请求体，但不会重复存储。
旧 UUID 图片地址保持有效，本次不扫描或迁移旧图片；去重查询针对新 MD5 命名图片。

## 存储与访问

图片保存在服务工作目录的 `uploads/images`，文件名由服务端计算的 MD5 和标准扩展名生成。
读取 `/uploads/images/<文件名>` 无需登录，适用于公共文档配图；不要上传私人资料。
部署时需持久化 `uploads` 目录、配置反向代理放行 `/uploads/`，并允许至少 11 MiB 的请求体。
当前不提供删除接口、文件元数据表或自动清理；备份需包含上传目录。

原 `POST /api/v1/upload/avatar` 保持原有行为。
Atlas 编辑器接入属于调用方后续工作，本次仅增加 Helios 通用接口。
