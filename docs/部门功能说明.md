# Helios 部门功能

日期：2026-11-03

## 范围

提供部门层级、新建与编辑、排序、启用／停用、多部门成员与负责人设置。用户无需填写部门编码；新建时后端自动生成内部兼容标识，编辑省略编码会保留旧值，关联仍使用稳定部门 ID，无需数据库迁移。管理员和超级管理员可维护；普通用户只能通过自己的部门接口读取本人归属。负责人仅作组织展示，不改变全局角色或项目身份。本次不开发任何资源分类或部门数据隔离。

## 部署

在 helios-auth-service 根目录执行：

```powershell
go run ./cmd/migrate-departments
go run ./cmd/api
```

迁移读取现有环境配置，事务内创建 departments 和 department_memberships 及约束索引，可重复执行，不导入旧 users.department 文本，不修改用户或项目角色。旧迁移目录存在重复 004 版本，因此本模块使用独立的显式迁移命令，不自动运行历史迁移。

前端更新后，管理员从“管理 → 部门管理”进入，地址 `/departments`。用户列表和个人资料展示正式多部门归属；旧部门文本保留为个人资料中的“注册部门备注”，不作为成员关系。

## 数据规则

- 账户审批必须提交至少一个启用部门的 department_ids 数组，可多选；审批、部门成员关系、部门版本及审批审计在同一事务提交，任一步失败整体回滚。
- 已审批的正常／锁定账户不得移出最后一个部门。调岗应先加入目标部门再移出原部门。锁定账户可补分配部门，但不会因此解锁；无部门的历史锁定账户不能直接解锁。
- 旧账户的空部门不会自动猜测补齐，管理员需要指定正式归属。可通过 `go run ./cmd/migrate-departments -check-unassigned` 只读统计存量情况。

- 同级部门名称、部门编码唯一。禁止循环层级，启用部门不能挂在停用部门下。
- 人员可属于多个部门；负责人必须是部门成员，移出时一并移除负责人标记。
- 新增成员允许已通过审批的正常／锁定用户；移出必须遵守至少保留一个部门的规则。
- 停用前必须移出全部成员，并停用或移走启用的下级部门。不物理删除部门。
- 每次部门或成员修改递增部门 version，客户端携带当前版本；冲突返回 409，刷新并重新打开操作后再提交。
- 组织变更事务内串行校验并同步写入现有 audit_logs，审计失败时整体回滚。

## 接口

用户管理支持“修改部门”：一次提交该用户的全部正式部门，至少一个；保留已有负责人身份、新成员默认非负责人。移出负责人所在部门必须明确确认。保存携带成员快照版本，冲突时重新加载，禁止覆盖其他管理员的成员或负责人变更。新增的 GET／PUT `/api/v1/org/users/:userId/departments` 均仅管理员可用，PUT 参数为 department_ids、expected_version、confirm_manager_removal；部门关系、受影响部门版本和审计在同一事务提交。不改变账户状态、全局角色和项目身份。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/v1/org/me | 本人正式部门列表，已登录有效用户可用 |
| GET | /api/v1/org/departments | 完整部门目录，含直接成员和负责人数 |
| POST | /api/v1/org/departments | 新建部门 |
| PUT | /api/v1/org/departments/:id | 更新名称、编码、上级、排序和状态；带 version |
| GET | /api/v1/org/departments/:id/members | 分页读取直接成员 |
| GET | /api/v1/org/departments/:id/members?candidates=true | 分页读取可添加的正常用户 |
| PUT | /api/v1/org/departments/:id/members/:userId | 加入成员或调整负责人，带 is_manager 和 version |
| DELETE | /api/v1/org/departments/:id/members/:userId | 移出当前部门，JSON 请求体携带 version |

除 `/org/me` 外均要求现有管理员或超级管理员角色。Cookie 会话的写请求要求匹配前端 Origin 和 CSRF 令牌。列表参数 page 从 1 开始，每页 20 条，q 按姓名／邮箱搜索。

## 验证

```powershell
go test ./internal/... ./cmd/...
$env:ORG_TEST_DB='1'
go test ./internal/organization -v
```

数据库集成测试使用配置数据库中的独立临时 schema，整个测试最终回滚，不修改现有用户、部门或项目数据。覆盖层级循环、重复名称与编码、多部门成员、负责人、停用限制、并发版本、分页、审计与管理角色边界。

前端在 helios-auth-admin 执行 `pnpm run check` 与 `pnpm run build`。资源系统以后单独接入，不因本次上线而自动获得部门功能。
